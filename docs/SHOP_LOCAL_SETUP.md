# Bazookatattoo: бесплатный полностью локальный тест магазина (Windows)

Ветка: `experiment/merch-shop-paypal-georgia`. Никакого деплоя. Этот режим не подключается к рабочему облачному Supabase, а создаёт отдельную базу, Auth, Storage и API на компьютере через Docker.

## Что уже есть в ветке
- `/merch.html`, `/en/merch.html`: каталог, выбор размера, корзина, регистрация, кабинет, сообщения, отзывы
- `/shop-admin.html`: товары, переписки, статусы заказов, промокоды, модерация отзывов
- Server-only Netlify Functions: сообщения, уведомления Telegram, PayPal Sandbox
- SQL: `supabase/schema.sql`, `supabase/shop-orders-migration.sql`, `supabase/shop-crm-migration.sql`
- `supabase/seed.sql`: три СИНТЕТИЧЕСКИХ товара с состояниями в наличии / нет в наличии; никаких существующих заказов и клиентов

## Установка без облака

Нужны Node.js 20+, Docker Desktop (должен быть запущен), PowerShell и доступ к интернету для загрузки CLI и Docker-образов.

1. Открой VS Code в репозитории Sacra Glyph, а не внутри вложенной случайной папки. В терминале:
   `git switch experiment/merch-shop-paypal-georgia`
   `git pull --ff-only`
2. Запусти в PowerShell из корня репозитория:
   `powershell -ExecutionPolicy Bypass -File .\scripts\setup-shop-local.ps1`
3. Скрипт проверит, что Supabase НЕ привязан к облаку, затем выполнит `supabase init`, подготовит миграции командой `supabase migration new`, запустит локальный Supabase, применит миграции и демо-seed, получит локальные ключи. Всё без `--remote` и без доступа к рабочей БД.
4. Автоматически создаст игнорируемый Git-файл `assets/js/shop-test-config.local.js` с **локальным публичным ключом** и локальный `.env` с **локальным серверным ключом** и предохранителями:
   `SHOP_CRM_TEST_MODE=1`, `SHOP_ALLOW_LOCAL_SUPABASE=1`, `SHOP_REQUIRE_LOCAL_DB=1`.
   Если `.env` существует и указывает на другую базу, скрипт остановится, не перезапишет файл.
5. В отдельном терминале:
   `npx --yes netlify-cli dev`
   Открой `http://localhost:8888/merch.html` и `http://localhost:8888/shop-admin.html`.
6. Локальная Supabase Studio: `http://127.0.0.1:54323`. Регистрационные письма обычно можно открыть через локальный Mailpit по адресу `http://127.0.0.1:54324` (посмотри вывод `npx supabase status`).

### Покупатель и администратор

В PowerShell выполни `node scripts/shop-test-accounts.mjs` один раз для новой пары тестовых аккаунтов. Скрипт выводит логины и случайные пароли для локальной базы. Храни их у себя. Каждый повторный запуск создаёт ещё одну пару.

Открой /merch.html в обычном окне и войди как buyer. В отдельном приватном окне открой /shop-admin.html и войди как admin. Добавь товар в наличии, выбери размер, страну и адрес, подтверди тест и нажми «Оформить локальный тестовый заказ». PayPal для этого сценария не нужен. Письмо появится в Mailpit на http://127.0.0.1:54324. Переведи заказ в «Доставлен» в админке, обнови кабинет покупателя, оставь отзыв и одобри его в админке.

### Telegram

В .env заполни SHOP_TG_CHAT_ID для тестового чата, в котором уже есть бот. Скопируй существующий токен основного сайта в SHOP_TG_BOT_TOKEN или используй уже настроенный TG_BOT_TOKEN. Для темы можно указать SHOP_TG_TOPIC_ID. Перезапусти Netlify Dev и нажми «Проверить Telegram-уведомление» в разделе «Сообщения». Интеграция выполняет исходящие отправки без изменения webhook.

### Почта

По умолчанию подтверждения локальных заказов видны в Mailpit. Для реального адреса укажи в .env SHOP_RECEIPT_TRANSPORT=resend, SHOP_RESEND_API_KEY и SHOP_RECEIPT_FROM (отправитель с подтверждённого домена). Перезапусти Netlify Dev и зарегистрируй покупателя со своим email. Для неотправленного письма предусмотрена кнопка повтора в разделе «Заказы». Письмо отправляется после подтверждения Sandbox-оплаты или локальной симуляции оплаты. Доставка согласуется отдельно.

### Полезные команды

- `npx --yes supabase status`: состояние локальной базы
- `npx --yes supabase stop`: остановить локальный Supabase, данные сохраняются
- `powershell -ExecutionPolicy Bypass -File .\scripts\setup-shop-local.ps1 -Reset`: сбросить **только локальные** тестовые данные
- Не запускать `supabase db reset --remote`, `supabase db push` или `supabase link` в эксперименте

## Что не подтверждено

Это подготовленный запуск, но **не пройденный E2E тест**. В текущей среде нет вашего Windows/Docker Desktop и локальных Telegram/PayPal Sandbox credentials. Протестируй регистрацию, вход, оба состояния товара, отправку сообщений в обе стороны, заказ, обновление статуса, промокод, отзыв с фото, админские права и реальные Sandbox-уведомления. Выпуск в `main` возможен только после проверки.
